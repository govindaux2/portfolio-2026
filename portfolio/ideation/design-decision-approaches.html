Approaches for articulating design decisions

Structured ideation for the hire-ready portfolio: different ways to show judgment under constraint, not a process diary. Use this to pick a narrative pattern per case study (Manufacturing → Nile → Kynder).

Purpose hiring / portfolio case studies Lens design decisions & trade-offs Status ideation — not locked Updated 3 Nov 2026, Asia/Calcutta

1. Goal what “good” means

Hiring managers cold-read in ~60 seconds. They hunt for: role clarity, contested choices, rejected alternatives, constraints, and honest outcomes. Final screens alone fail that scan.

Avoid

Chronological UX-process dump · “I did research then wireframes” · metric invention · framework diagrams with no turning points

Aim for

2–3 consequential decisions · named alternatives · accepted cost · evidence (or honest uncertainty) · what you’d revisit

3. Approach cards mechanics + copy

Each card: when to use, structure, copy template, and a weak vs strong example.

Approach A

Expected direction vs My call

UI / principle Scannable Steal from Roach

You rejected the “industry default” (photo-rich humanitarian site, fancy custom system, agent that auto-acts) for a constraint-led choice.

  • Context — constraint in one line
  • Expected — what most teams would ship
  • My call — what you chose + why
Expected
[Default / tempting direction]

My call
[Actual choice]
Because [constraint / principle].

Weak

“We kept the UI simple and accessible.”

Strong (agent UX flavor)

Expected: fully autonomous agent that executes plant actions. My call: Insight → Action with explicit approval gates — because audit liability beats speed when a wrong run stops a line.

Approach B

Rejected alternative (reasoning layer)

Hiring callback One sentence Cold-read critical

Every major choice. Minimum one “what I didn’t do” per case study — this is what many portfolios skip.

  • Chose X
  • Over Y
  • Because Z constraint / evidence
I chose [X] over [Y]
because [Z made Y wrong / premature / unsafe].
The cost I accepted: [limitation].
Approach C

Evidence → interpretation → decision → tradeoff → effect

Research-backed 2–3 decisions max The Crit

You have real signals (interviews, ops shadowing, logs, usability). Mark unknowns [NEED INPUT] rather than inventing lifts.

Evidence: [what we saw]
Interpretation: [what it meant]
Decision: [what we shipped]
Tradeoff: [what we gave up]
Effect: [observed / tested / unknown]
Approach D

Decision triangle (user · business · constraint)

Strategic framing DesignCase

Stakeholder fights (“just add chat”) need a crisp frame that shows you balanced three forces — useful in Manufacturing approval UX.

User need: …
Business goal: …
Constraint: …
→ Decision: …
Approach E

PUXD 5-field decision log

Working method During build Then prune
  • Decision — plain statement
  • Evidence / reasoning — what you knew then
  • Alternatives rejected — and why
  • Constraints — tech, policy, time, org
  • Revisit when — conditions that reopen it

Keep logs in phase markdown (/portfolio/mfg). Promote only the best 2–3 into the public case study; leave the rest as interview ammo.

Approach F

Contested call (name the conflict)

Priority fights Interview gold

Multiple goods compete for one surface (speed vs audit, autonomy vs control, density vs glanceability).

Conflict: [A], [B], and [C] all wanted first place.
Reasoning tool: [your hierarchy / principle].
What tipped it: [evidence or constraint].
Accepted cost: [what lost].
Approach G

Numbered decision series

Long projects Amazon-style

Platform / multi-month work where order of bets matters. Use sparingly — cold readers won’t finish Decision 08 of 08.

Show 3 numbered decisions on-page; collapse the rest behind “More decisions” or keep for live walkthrough.

Approach H

Cold-read 4-block skeleton

Case study spine Default layout
  • Problem — constraint you designed within
  • Process — what you actually did (short)
  • Decisions — what you chose not to do, and why
  • Outcomes — what changed + how you know (or don’t)

Aligns with FigJam “universal 10-section spine” — treat Decisions as the limelight section, not another process rename.

Approaches I & J

Inverted pyramid + What / How / Why captions

Page craft Doody · IxDF

Lead with outcome + role + one decision headline so recruiters stop skimming. Depth below for hiring managers.

Caption only artifacts that carry a turning point. Skip decorative galleries of every wireframe.

4. Recommended combos how to mix

Don’t use all ten on one page. Pick a skeleton + 1–2 decision formats.

Combo 1 — Default for Manufacturing (M1+)

  1. H Cold-read 4-block as page spine
  2. A + F Hero decision as Expected vs My call + contested approval gate
  3. B One explicit rejected path (full autonomy)
  4. C Only where evidence exists; else [NEED INPUT]

Combo 2 — Nile (systems / triage)

  1. H spine + I impact-first opening
  2. D triangle for network vs client priority fights
  3. G optional short numbered series (3 max) for platform bets

Combo 3 — Kynder (draft → review → send)

  1. A Expected auto-send vs My call human review
  2. B + C rejected “parent blast without review” with research chain
  3. J caption prototype states that show the gate

Combo 4 — Working method (offline)

  1. Keep E PUXD logs in phase folders while building
  2. At publish time, promote 2–3 into public case; rest = interview kit

5. Working recommendation lock later

Proposed default for this portfolio

Spine: Cold-read 4-block (H). Hero decision format: Expected vs My call (A) + Contested call (F). Mandatory sentence: Rejected alternative (B) at least once per case. Evidence: Chain (C) only with real or labeled proxy data — no invented production metrics.
